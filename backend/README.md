# Opti-Bot — Backend

Бот для WhatsApp: отвечает на частые вопросы из базы знаний, сложные — отдаёт ИИ,
по запросу переводит на оператора.

## Стек

FastAPI · PostgreSQL · Redis · Green-API (WhatsApp) · Cerebras (LLM)

## Готово

- Каркас проекта (`app/core`, `app/api`, `app/db`, `app/services`, `app/schemas`)
- Клиент Green-API: отправка сообщений, поллинг очереди (`app/services/green_api.py`)
- Клиент Cerebras (`app/services/cerebras.py`)
- Вебхук `POST /api/v1/whatsapp/webhook` + скрипт поллинга `scripts/whatsapp_reply_bot.py`
- `docker-compose.yml` (Postgres + Redis), Alembic настроен

Этап 1 подключён: "сообщение → поиск в базе знаний → совпадение? ответ оттуда : Cerebras". Ниже — что осталось до демо всех трёх этапов.

---

## Этап 1 — База знаний

- [x] Таблица `knowledge_base` (question, answer) + миграция
- [x] Простой поиск: fuzzy-match вопроса по таблице (`difflib`, без embeddings/pgvector)
- [x] Если совпадение выше порога — отвечаем сразу из базы, без Cerebras

## Этап 2 — Ответ ИИ

- [x] Если совпадения в базе знаний нет — вопрос уходит в Cerebras с системным промптом
- [x] В промпт вставляется топ-3 похожих записей из базы знаний как контекст (мини-RAG на `difflib`,
      без отдельной инфраструктуры; ниже порога точного совпадения, но выше 0.2 — как подсказка,
      не как готовый ответ)

## Этап 3 — Перевод на оператора

- [x] Детект по ключевым словам ("оператор", "человек", "менеджер") в сообщении
- [x] Флаг `conversation.escalated = true` — бот перестаёт отвечать в этом чате
- [x] Уведомление о переводе: лог в консоль + WhatsApp-сообщение на `OPERATOR_CHAT_ID` (если задан
      в `.env`), без очереди и таймаутов

## Сквозное (нужно для всех этапов)

- [x] Таблицы `conversation` / `message` в Postgres — хранить историю переписки
      (нужна и для контекста в Cerebras, и чтобы понять, что диалог уже эскалирован)
- [x] Дедупликация входящих сообщений по `idMessage` (Redis, TTL 24ч) — общая для вебхука и
      скрипта поллинга, обе точки входа передают `message_id` в `handle_incoming_message`

Все пункты сквозного плана закрыты — можно собирать демо всех трёх этапов.

## Осознанно не делаем на хакатон

Мультиарендность (несколько учреждений), авторизация/JWT, rate limiting, очереди (Celery/RQ),
CI, семантический поиск (pgvector) — по одной институции без этого демо соберётся быстрее.
Возвращаемся к этому после хакатона.

## ⚠ Известный блокер

Ключ `CEREBRAS_API_KEY` в `.env` рабочий, но аккаунт без кредитов — любой запрос к чату (обе
доступные ключу модели, `qwen-3.8-27b` и `gpt-oss-120b`) отдаёт `402 Payment Required`. Это не
чинится кодом — нужно пополнить баланс на cloud.cerebras.ai до демо, иначе Этап 2 (и любой
вопрос без совпадения в базе знаний) не ответит.
