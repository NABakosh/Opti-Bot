# Opti-Bot — Backend

Бот для WhatsApp: отвечает на частые вопросы из базы знаний, сложные — отдаёт ИИ,
по запросу переводит на оператора.

## Стек

FastAPI · PostgreSQL · Redis · Green-API (WhatsApp) · Cerebras (LLM)

## Готово

- Каркас проекта (`app/core`, `app/api`, `app/db`, `app/services`, `app/schemas`)
- Клиент Green-API: отправка сообщений, поллинг очереди (`app/services/green_api.py`)
- Клиент Cerebras (`app/services/cerebras.py`)
- Вебхук `POST /api/v1/whatsapp/webhook` + скрипт поллинга `scripts/whatsapp_reply_bot.py`
- `docker-compose.yml` (Postgres + Redis), Alembic настроен

Сейчас это прямой проброс "сообщение → Cerebras → ответ". Ниже — минимум, чтобы собрать демо трёх этапов.

---

## Этап 1 — База знаний

- [ ] Таблица `knowledge_base` (question, answer) + миграция
- [ ] Простой поиск: fuzzy/keyword-match вопроса по таблице (без embeddings/pgvector — не хватит времени)
- [ ] Если совпадение выше порога — отвечаем сразу из базы, без Cerebras

## Этап 2 — Ответ ИИ

- [ ] Если совпадения в базе знаний нет — вопрос уходит в Cerebras с системным промптом
- [ ] В промпт можно просто вставить топ-N похожих записей из базы знаний как контекст (мини-RAG,
      без отдельной инфраструктуры)

## Этап 3 — Перевод на оператора

- [ ] Детект по ключевым словам ("оператор", "человек", "менеджер") в сообщении
- [ ] Флаг `conversation.escalated = true` — бот перестаёт отвечать в этом чате
- [ ] Уведомление о переводе — простое сообщение оператору (Telegram/лог в консоль/фикс. номер
      в WhatsApp), без очереди и таймаутов

## Сквозное (нужно для всех этапов)

- [ ] Таблицы `conversation` / `message` в Postgres — хранить историю переписки
      (нужна и для контекста в Cerebras, и чтобы понять, что диалог уже эскалирован)
- [ ] Дедупликация входящих вебхуков по `idMessage` (Redis) — Green-API может прислать
      уведомление повторно, без дедупликации бот ответит дважды

## Осознанно не делаем на хакатон

Мультиарендность (несколько учреждений), авторизация/JWT, rate limiting, очереди (Celery/RQ),
CI, семантический поиск (pgvector) — по одной институции без этого демо соберётся быстрее.
Возвращаемся к этому после хакатона.
